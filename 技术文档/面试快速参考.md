# 大文件上传 - 面试快速参考卡

## 🎯 30秒项目介绍

> "我实现了一个大文件上传功能，支持GB级别文件上传、断点续传、实时进度显示。主要使用了Web Worker、IndexedDB、WebSocket等技术，解决了大文件上传的痛点问题。"

---

## 📊 核心数据（记住这些数字）

- **支持文件大小**: GB级别（实际测试过5GB+）
- **分片大小**: 2MB（可配置）
- **并发数**: 3个（可配置）
- **上传成功率**: 从60%提升到95%+
- **Hash计算时间**: 5GB文件约3-5分钟（Web Worker，不阻塞）

---

## 🔑 关键技术点（必背）

### 1. 分片上传
- **原因**: 网络容错、内存友好、支持断点续传
- **实现**: File.slice() 零拷贝切片

### 2. Web Worker
- **原因**: 避免主线程阻塞，保持页面流畅
- **实现**: 后台线程处理切片和Hash计算

### 3. IndexedDB
- **原因**: 大容量存储、支持二进制数据、持久化
- **实现**: 保存分片数据和上传进度

### 4. WebSocket
- **原因**: 实时通信、服务器主动推送、降低服务器压力
- **实现**: 实时推送上传进度和状态

### 5. 后端合并
- **原因**: 内存占用低、支持断点续传、服务器处理能力强
- **实现**: 分片上传完成后调用合并接口

---

## 💡 核心问题标准答案（一句话版）

| 问题 | 答案 |
|------|------|
| **为什么分片上传？** | 网络容错、内存友好、支持断点续传 |
| **为什么用Web Worker？** | 避免主线程阻塞，保持页面流畅 |
| **为什么用IndexedDB？** | 大容量存储、支持二进制数据、持久化 |
| **为什么后端合并？** | 内存占用低、服务器处理能力强 |
| **如何断点续传？** | 文件Hash + IndexedDB保存进度 + 只上传未完成分片 |
| **如何控制并发？** | 请求队列，控制运行数不超过最大并发数 |
| **如何计算进度？** | 基于已上传分片计算已上传字节数 / 文件总大小 |
| **如何处理错误？** | 自动重试（最多3次）+ 指数退避 + 错误提示 |

## 🔧 技术架构（一句话）

```
用户选择文件 
→ Web Worker切片和Hash计算 
→ IndexedDB保存分片和进度 
→ 请求队列控制并发上传 
→ WebSocket实时推送进度 
→ 所有分片上传完成 
→ 调用后端合并接口 
→ 清理IndexedDB 
→ 完成
```

## 🚨 常见追问（快速回答）

| 追问 | 快速回答 |
|------|---------|
| **10GB文件能用吗？** | 可以，调整分片大小和并发数，服务器端使用流式处理 |
| **关闭浏览器怎么办？** | IndexedDB持久化，重新打开后可恢复进度 |
| **如何防止重复上传？** | 文件Hash作为唯一标识，服务器端检查，支持秒传 |
| **如何保证文件完整性？** | 分片Hash + 文件Hash + 大小校验 |
