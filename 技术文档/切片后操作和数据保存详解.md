# 切片后操作和数据保存详解

## 📋 切片后的完整流程

### 核心流程

```
文件切片
    ↓
计算分片 Hash
    ↓
保存分片到 IndexedDB
    ↓
保存文件元数据到 IndexedDB
    ↓
上传分片（从 IndexedDB 读取）
    ↓
上传完成后清理 IndexedDB
```

## 💾 数据保存位置：IndexedDB

### 为什么保存在 IndexedDB？

1. **大容量存储**
   - IndexedDB 可以存储几GB数据
   - localStorage 只有 5-10MB

2. **支持二进制数据**
   - IndexedDB 可以直接存储 Blob
   - localStorage 只能存储字符串

3. **持久化存储**
   - 页面刷新后数据不丢失
   - 支持断点续传

4. **异步操作**
   - 不阻塞主线程
   - 性能好

### IndexedDB 存储结构

```typescript
// 数据库：FileUploadDB

```

## 🔄 数据使用流程

### 1. 上传时从 IndexedDB 读取分片

**位置：** `src/classes/uploadFile.ts` - `uploadChunk()`

```typescript
private async uploadChunk(chunk: ChunkInfo): Promise<void> {
  // 从 IndexedDB 获取分片（如果存在）
  let blob = chunk.blob
  const savedBlob = await indexedDBManager.getChunk(this.file.id, chunk.index)
  if (savedBlob) {
    blob = savedBlob  // 🔑 使用 IndexedDB 中的分片
  }

  // 创建 FormData
  const formData = new FormData()
  formData.append('file', blob)  // 使用从 IndexedDB 读取的分片
  // ...
}
```

### 2. 断点续传时恢复分片

**位置：** `src/classes/uploadFile.ts` - `restoreFromMetadata()`

```typescript
private async restoreFromMetadata(metadata: FileMetadata): Promise<void> {
  // 从 IndexedDB 加载分片
  const savedChunks = await indexedDBManager.getAllChunks(metadata.fileId)
  
  if (savedChunks.length > 0) {
    // 使用保存的分片
    this.chunks = savedChunks
    this.file.chunkList = this.chunks
    
    // 恢复已上传的分片索引
    this.uploadedChunkIndices = new Set(metadata.uploadedChunks)
  }
}
```

### 3. 上传完成后清理数据

**位置：** `src/classes/uploadFile.ts` - `start()`

```typescript
// 所有分片上传完成后，合并分片
if (this.uploadedChunkIndices.size === this.chunks.length) {
  await this.mergeChunks()
  this.file.status = 'success'
  
  // 🔑 清理 IndexedDB 中的数据
  await indexedDBManager.deleteChunks(this.file.id)
  await indexedDBManager.deleteFileMetadata(this.file.id)
}
```

## 🎯 为什么需要保存分片数据？

### 1. 断点续传

```typescript
// 场景：用户上传到一半，关闭了浏览器

// 如果没有保存分片：
// ❌ 需要重新切片，重新计算Hash，浪费时间

// 如果保存了分片：
// ✅ 可以直接从 IndexedDB 恢复分片
// ✅ 只上传未完成的分片
```

### 2. 网络中断恢复

```typescript
// 场景：网络中断后恢复

// 如果没有保存分片：
// ❌ File 对象丢失，无法恢复

// 如果保存了分片：
// ✅ 从 IndexedDB 读取分片，继续上传
```

### 3. 页面刷新恢复

```typescript
// 场景：用户刷新页面

// 如果没有保存分片：
// ❌ 上传进度丢失，需要重新上传

// 如果保存了分片：
// ✅ 从 IndexedDB 恢复上传进度
// ✅ 继续上传未完成的分片
```

## 💡 数据保存的关键代码

### 1. 保存分片

```typescript
// src/utils/indexedDB.ts

async saveChunk(
  fileId: string,
  chunkIndex: number,
  blob: Blob,
  hash?: string
): Promise<void> {
  const transaction = this.db!.transaction([STORE_CHUNKS], 'readwrite')
  const store = transaction.objectStore(STORE_CHUNKS)

  const chunkData = {
    id: `${fileId}_${chunkIndex}`,  // 唯一ID
    fileId,
    chunkIndex,
    blob,                            // 🔑 分片数据（Blob）
    hash,                            // 分片Hash
    createdAt: Date.now()
  }

  await store.put(chunkData)  // 保存到 IndexedDB
}
```

### 2. 读取分片

```typescript
// src/utils/indexedDB.ts

async getChunk(fileId: string, chunkIndex: number): Promise<Blob | null> {
  const transaction = this.db!.transaction([STORE_CHUNKS], 'readonly')
  const store = transaction.objectStore(STORE_CHUNKS)
  const request = store.get(`${fileId}_${chunkIndex}`)
  
  return new Promise((resolve) => {
    request.onsuccess = () => {
      resolve(request.result?.blob || null)  // 🔑 返回分片数据
    }
  })
}
```

### 3. 获取所有分片

```typescript
// src/utils/indexedDB.ts

async getAllChunks(fileId: string): Promise<ChunkInfo[]> {
  const transaction = this.db!.transaction([STORE_CHUNKS], 'readonly')
  const store = transaction.objectStore(STORE_CHUNKS)
  const index = store.index('fileId')
  const request = index.getAll(fileId)
  
  return new Promise((resolve) => {
    request.onsuccess = () => {
      const chunks = request.result.map(item => ({
        index: item.chunkIndex,
        start: item.chunkIndex * CHUNK_SIZE,  // 需要重新计算
        end: (item.chunkIndex + 1) * CHUNK_SIZE,
        blob: item.blob,                      // 🔑 从 IndexedDB 读取
        hash: item.hash
      }))
      resolve(chunks)
    }
  })
}
```

## ✅ 总结

### 切片后的操作

1. ✅ **计算分片 Hash** - 验证分片完整性
2. ✅ **保存分片到 IndexedDB** - 支持断点续传
3. ✅ **保存文件元数据** - 记录上传进度
4. ✅ **上传时从 IndexedDB 读取** - 使用保存的分片
5. ✅ **上传完成后清理** - 释放存储空间

### 数据保存位置

- **分片数据**：IndexedDB → `chunks` 对象存储
- **文件元数据**：IndexedDB → `files` 对象存储

### 为什么需要保存？

- ✅ **断点续传** - 页面刷新后可恢复
- ✅ **网络中断恢复** - 网络恢复后继续上传
- ✅ **避免重复计算** - 不需要重新切片和计算Hash
