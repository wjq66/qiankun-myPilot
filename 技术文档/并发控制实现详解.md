# 并发控制实现详解

## 📋 项目中的并发控制

项目中实现了**三层并发控制**，分别用于不同的场景：

1. **请求队列（RequestQueue）** - 控制分片上传的并发数量 ⭐⭐⭐⭐⭐
2. **批量Hash计算** - 控制分片Hash计算的并发数量 ⭐⭐⭐
3. **多文件上传** - 控制多个文件同时上传的数量 ⭐⭐⭐⭐

## 🎯 第一层：请求队列（RequestQueue）- 核心实现

### 实现位置
`src/utils/requestQueue.ts`

### 核心思路

**使用队列 + 运行计数器** 控制并发数量：

```typescript
export class RequestQueue {
  private queue: QueueTask[] = []           // 任务队列
  private running: Set<string> = new Set()  // 运行中的任务ID集合
  private concurrent: number = 3             // 最大并发数

  /**
   * 处理队列的核心方法
   */
  private async processQueue(): Promise<void> {
    // 🔑 关键：检查是否达到并发限制
    if (this.running.size >= this.concurrent) {
      return  // 已达到并发限制，等待
    }

    // 如果队列为空，返回
    if (this.queue.length === 0) {
      return
    }

    // 取出任务
    const task = this.queue.shift()
    
    // 标记为运行中
    this.running.add(task.id)  // 🔑 关键：增加运行计数

    try {
      // 执行任务
      const result = await this.executeTask(task)
      task.resolve(result)
    } catch (error) {
      // 错误处理...
    } finally {
      // 🔑 关键：任务完成后，从运行中移除
      this.running.delete(task.id)
      // 继续处理下一个任务
      this.processQueue()  // 🔑 关键：递归调用，处理下一个任务
    }
  }
}
```

### 关键代码

```typescript
/**
 * 添加任务到队列
 */
add(task: QueueTask): Promise<any> {
  return new Promise((resolve, reject) => {
    const taskWithCallbacks = {
      ...task,
      resolve,
      reject,
      retry: task.retry ?? this.defaultRetry,
      retryDelay: task.retryDelay ?? this.defaultRetryDelay
    }

    // 按优先级插入队列
    this.insertTask(taskWithCallbacks)
    // 🔑 关键：添加任务后立即尝试处理队列
    this.processQueue()
  })
}

/**
 * 处理队列（核心方法）
 */
private async processQueue(): Promise<void> {
  // 🔑 关键1：检查并发限制
  if (this.running.size >= this.concurrent) {
    return  // 已达到并发限制，等待
  }

  // 🔑 关键2：检查队列是否为空
  if (this.queue.length === 0) {
    return
  }

  // 🔑 关键3：取出任务
  const task = this.queue.shift()
  if (!task) {
    return
  }

  // 🔑 关键4：标记为运行中（增加运行计数）
  this.running.add(task.id)

  // 🔑 关键5：执行任务（异步）
  try {
    const result = await this.executeTask(task)
    task.resolve(result)
  } catch (error) {
    // 错误处理和重试...
  } finally {
    // 🔑 关键6：任务完成后，从运行中移除（减少运行计数）
    this.running.delete(task.id)
    // 🔑 关键7：继续处理下一个任务（递归调用）
    this.processQueue()
  }
}
```

### 在分片上传中的应用

```typescript
// src/classes/uploadFile.ts

/**
 * 上传待上传的分片
 */
private async uploadPendingChunks(): Promise<void> {
  // 找出未上传的分片
  const pendingChunks = this.chunks.filter(
    (_, index) => !this.uploadedChunkIndices.has(index)
  )

  if (pendingChunks.length === 0) {
    return
  }

  // 🔑 关键：使用请求队列上传分片（自动控制并发）
  const uploadPromises = pendingChunks.map(chunk =>
    requestQueue.add({
      id: `${this.file.id}_${chunk.index}`,
      execute: () => this.uploadChunk(chunk),  // 执行上传
      priority: 0
    })
  )

  // 等待所有分片上传完成
  await Promise.all(uploadPromises)
}
```

```typescript
/**
 * 批量计算分片 Hash（并发）
 */
async calculateChunkHashes(
  chunks: ChunkInfo[],
  concurrent: number = 3
): Promise<void> {
  // 🔑 关键：分批处理，每批 concurrent 个
  for (let i = 0; i < chunks.length; i += concurrent) {
    // 取出一批分片
    const batch = chunks.slice(i, i + concurrent)
    
    // 🔑 关键：并发计算这一批的 Hash
    const batchPromises = batch.map(chunk =>
      this.calculateChunkHash(chunk.blob, chunk.index)
    )
    
    // 等待这一批完成
    await Promise.all(batchPromises)
    
    // 🔑 关键：这一批完成后，继续处理下一批
  }
}
```

### 工作原理

```
假设有 10 个分片需要计算 Hash，并发数为 3：

批次1：chunk0, chunk1, chunk2
  → Promise.all([hash0, hash1, hash2])
  → 等待完成

批次2：chunk3, chunk4, chunk5
  → Promise.all([hash3, hash4, hash5])
  → 等待完成

批次3：chunk6, chunk7, chunk8
  → Promise.all([hash6, hash7, hash8])
  → 等待完成

批次4：chunk9
  → Promise.all([hash9])
  → 等待完成
```

```typescript
async function uploadAll() {
  const pendingFiles = fileList.value.filter(file => file.status === 'pending')
```

## 🔑 核心设计模式

### 1. 队列模式（Queue Pattern）

```typescript
// 使用队列存储待处理的任务
private queue: QueueTask[] = []

// 按顺序处理队列中的任务
const task = this.queue.shift()
```

### 2. 运行计数器模式（Running Counter Pattern）

```typescript
// 使用 Set 记录运行中的任务
private running: Set<string> = new Set()

// 检查并发限制
if (this.running.size >= this.concurrent) {
  return  // 等待
}

// 任务开始时增加计数
this.running.add(task.id)

// 任务完成时减少计数
this.running.delete(task.id)
```

### 3. 递归处理模式（Recursive Processing Pattern）

```typescript
// 任务完成后，递归调用处理下一个任务
finally {
  this.running.delete(task.id)
  this.processQueue()  // 🔑 递归调用
}
```

## 💡 为什么使用这种实现方式？

### 1. 为什么用队列而不是 Promise.all()？

```typescript
// ❌ 错误：所有请求同时发送
await Promise.all(chunks.map(chunk => uploadChunk(chunk)))
// 问题：如果100个分片，会同时发送100个请求，服务器压力大

// ✅ 正确：通过队列控制并发
chunks.forEach(chunk => {
  requestQueue.add({
    execute: () => uploadChunk(chunk)
  })
})
// 优势：最多同时3个请求，服务器压力小
```

### 2. 为什么用 Set 记录运行中的任务？

```typescript
// ✅ 使用 Set 的优势：
// 1. 快速查找：O(1) 时间复杂度
// 2. 自动去重：不会重复添加
// 3. 快速删除：O(1) 时间复杂度
private running: Set<string> = new Set()

// 如果使用数组：
// ❌ 查找：O(n)
// ❌ 删除：O(n)
private running: string[] = []
```

### 3. 为什么递归调用 processQueue()？

```typescript
// ✅ 递归调用的优势：
// 1. 自动处理下一个任务
// 2. 代码简洁
// 3. 不需要额外的轮询机制

finally {
  this.running.delete(task.id)
  this.processQueue()  // 自动处理下一个
}

// 如果不用递归：
// ❌ 需要手动轮询
// ❌ 代码复杂
setInterval(() => {
  if (this.running.size < this.concurrent) {
    this.processQueue()
  }
}, 100)
```

## 📝 总结

### 核心实现

1. **队列存储任务** - `queue: QueueTask[]`
2. **Set 记录运行中** - `running: Set<string>`
3. **检查并发限制** - `running.size >= concurrent`
4. **递归处理** - 任务完成后自动处理下一个

### 关键代码

```typescript
// 核心逻辑
if (this.running.size >= this.concurrent) {
  return  // 达到并发限制，等待
}

this.running.add(task.id)  // 增加计数
await task.execute()        // 执行任务
this.running.delete(task.id)  // 减少计数
this.processQueue()        // 处理下一个
```

### 优势

- ✅ 控制并发数量，避免服务器压力
- ✅ 代码简洁，易于理解
- ✅ 支持优先级和重试
- ✅ 自动处理，无需手动管理
